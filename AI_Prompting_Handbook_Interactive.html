AI Prompting Handbook

A practical guide to writing clear, effective and reusable prompts for text, analysis, software testing, AI agents, automation, images and infographics.

Workplace-ready Reusable templates Responsible AI

How to use this handbook

Use this handbook when you need to plan, write, improve or review an AI prompt. The examples are designed to be adapted across office work, HR, software testing, research, analysis, communication and AI-enabled workflows.

Core idea: A good prompt reduces ambiguity. It tells the AI what you want, gives it the context it needs, defines useful boundaries and makes the expected output easy to understand.

Three ways to use it

Learn

Start with Prompt Engineering, LLM Settings, Prompt Elements and Techniques.

Apply

Copy and adapt the templates for workplace tasks, testing, agents, images and infographics.

Review

Use the Responsible AI section and Prompt Checklist before important AI-assisted work.

Important: AI output is not automatic truth. Verify important facts, calculations, legal or policy claims, technical conclusions and any output that could materially affect people or business decisions.
Foundations

Prompt Engineering

Prompt engineering is the practice of designing and refining instructions, context and examples so an AI model is more likely to produce useful output.

What is a prompt?

A prompt is the instruction, question, context, data or other input you give an AI system to guide its response. Prompts can contain text, documents, images, audio or structured data depending on the system.

Summarize this meeting note in five bullet points.

A structured prompt

Act as a project coordinator.
Review the meeting notes below.
Identify decisions, action items, owners and deadlines.
Return a four-column table.
Do not invent missing owners or dates; mark them as "Not specified."
Think of prompting as briefing a capable colleague. The clearer the brief, the easier it is to produce work that matches your purpose. Good prompting is less about magic words and more about clear thinking.

What prompts can control

Task & context

  • What the AI should do
  • What it needs to know
  • Relevant source material

Audience & output

  • Who the answer is for
  • Length, tone and scope
  • Table, memo, checklist, JSON, etc.

Start with the outcome

Weak objectiveStronger objective
Tell me about customer service.Create a one-page briefing for new customer-service employees explaining five behaviors that improve difficult customer conversations. Use plain language and give one example phrase for each behavior.

Give the right context

Too littleUseful context
Write an onboarding email.Write a first-day onboarding email for a new employee joining an international airline operations team.
Create test cases.Create system test cases for a password-reset user story in a customer portal.
Summarize this.Summarize the attached policy for non-technical employees who need the key actions, not legal detail.

Use constraints carefully

Constraints guide the response. Useful constraints include length, tone, scope, evidence rules, safety rules, output format and instructions for handling uncertainty.

Avoid conflicting instructions. “Be comprehensive” and “maximum 50 words” can conflict. State priorities when requirements compete.

Specify the output format

Compare the three options in a table with columns for benefits, risks, cost considerations, implementation effort and recommendation. Follow the table with a five-sentence executive summary.

Use examples to show what good looks like

Examples are useful when tone, structure, labels, classification or level of detail matter. If an example is only illustrative, say so.

Break complex work into steps

Understand — identify the objective, audience and missing information.
Analyze — extract requirements, evidence and risks.
Create — draft the requested output.
Review — check the draft against the requirements.
Refine — improve weak areas without changing approved content.

Iterate

  • What assumptions did you make?
  • What information is missing?
  • Give me three alternatives with different tones.
  • Check your answer against the original requirements.
  • Shorten this by 30% without removing key actions.
  • Turn this into a reusable template with placeholders.
LLM Settings

Model and Generation Settings

Settings influence how a trained model generates output. They are different from the model’s learned parameters.

Parameters vs. inference settings

Model parameters

Learned numerical values inside the neural network. They are adjusted during training and collectively determine how the model transforms inputs into outputs.

Inference settings

Controls used when the trained model generates a response. Availability varies by model and platform.

Common generation settings

SettingSimple definitionPractical effect
TemperatureControls how strongly generation favors the most likely next tokens.Lower values are usually more predictable; higher values can increase variation.
Top-pLimits token sampling to a probability mass (“nucleus sampling”).Can control diversity by restricting the candidate token set.
Max output tokensLimits how much the model may generate.Useful for controlling length and cost; output can be cut off if the limit is too small.
Frequency / presence penaltiesOptional controls in some APIs that discourage repetition or encourage new terms/topics.Useful in some generation tasks; support varies by model.
Seed / deterministic controlsSome systems offer controls that make repeated runs more reproducible.Reproducibility is not always guaranteed.
Professional rule: Prefer prompt clarity before tuning settings. Settings can shape generation, but they do not repair missing context, unclear goals or weak source material.

Knowledge freshness

Do not assume a model knows current information. Some AI systems can use web search or connected sources; others cannot. For time-sensitive questions, explicitly request current verification and authoritative sources when tools are available.

Core Framework

Prompt Elements

A reliable professional prompt usually combines a clear instruction with context, relevant input and a defined output.

The professional five-part framework

ROLE + TASK + CONTEXT + CONSTRAINTS + OUTPUT

ElementQuestion to askExample
RoleWhat perspective is useful?You are an HR learning specialist.
TaskWhat exactly should happen?Create a 60-minute onboarding workshop.
ContextWhat should the AI know?Audience: new international employees.
ConstraintsWhat rules or limits apply?Plain English; max 6 activities; no jargon.
OutputHow should the result look?Agenda table with time, activity and purpose.

Four core components

  1. Instruction: the action the AI should perform.
  2. Context: background information, role, audience or examples.
  3. Input data: source material such as text, logs, requirements or a document.
  4. Output format: the structure the result should take.

Example

You are an HR learning specialist.

TASK
Create a 60-minute onboarding workshop.

CONTEXT
Audience: new international employees.

CONSTRAINTS
Use simple language. Include no more than six activities.

OUTPUT
Return an agenda table with time, activity, facilitator instructions and purpose.
Practical Tips

General Tips for Designing Prompts

Use these as habits, not rigid rules. Different models and tasks can respond differently.

Practical guidance

TipWhat it means
Assign a role when usefulA role can establish perspective, vocabulary or priorities. It does not guarantee expert-level accuracy.
Prefer positive instructionsSay what the AI should do, not only what it should avoid. Negative rules are still useful for hard boundaries.
Use normal, clear capitalizationClear headings and structure matter more than ALL CAPS.
Account for freshnessIf the answer depends on current facts, request verification with current authoritative sources when tools are available.
Ask for a preview or outlineFor complex deliverables, request the structure first and approve it before full generation.
Define the audienceSpecify expertise level, role or decision context when it changes the answer.
Place instructions clearlyUse headings or delimiters to separate instructions from source material.
Save proven promptsStore useful prompts with version, owner, use case and review rules.
Specify tone, not emotional manipulationAsk for professional, reassuring or energetic tone. Emotional-pressure claims are experimental, not a general rule.
Use Markdown for long promptsHeadings and bullet points improve readability.

Use delimiters for source material

Summarize the text below. Use only the supplied text.

TEXT
"""
[paste source here]
"""

OUTPUT
- 5 key points
- 3 actions
- Missing or unclear information
Core Techniques

Prompting Techniques

Choose the simplest technique that reliably solves the task. More elaborate prompting is not automatically better.

Technique overview

TechniqueDefinitionExample use
Zero-shot promptingAsk the model to perform a task without examples.Classify feedback as positive, neutral or negative.
One-shot promptingProvide one example of the desired input-output behavior.Show one correctly formatted defect report.
Few-shot promptingProvide several examples so the model can infer the pattern.Show 3 labeled support messages before classification.
Chain-of-thought promptingA research technique that elicits intermediate reasoning steps; many systems do not expose hidden internal reasoning.For professional use, request a concise rationale or verification steps.
Meta promptingAsk the model to improve, critique or design a prompt.Rewrite this prompt to reduce ambiguity.
Self-consistencyGenerate multiple candidate paths or answers and compare/aggregate them.Check robustness on reasoning tasks.
Generate-knowledge promptingAsk the model to identify relevant background knowledge before answering.Useful for brainstorming; generated knowledge must be verified.
Prompt chainingBreak a workflow into linked prompts where one output becomes input to the next step.Extract requirements → risks → tests → review.
Tree of ThoughtsExplore multiple candidate paths, compare them, then continue with stronger options.Complex planning and search.
RAGRetrieve relevant external information and provide it to the model before generation.Answer questions using approved company policies.
ReAct / tool useCombine reasoning with actions such as search, calculation or API calls.An agent searches, checks data and drafts an answer.

Zero-shot → few-shot → workflow

Start simple: try a clear zero-shot instruction.
Add examples: use one-shot or few-shot when labels or style are inconsistent.
Decompose: split complex work into a chain with checkpoints.
Add retrieval/tools: use RAG or tools when current, private or verifiable information is required.
Evaluate: measure quality before automating.
Chain-of-thought note: request useful observable evidence such as assumptions, formulas, supporting facts or concise rationale rather than hidden internal reasoning.
Examples

From Vague to Useful

Specificity improves reliability and reduces revision.

1. Image generation

Unclear

“Create an image of a young man.”

Improved

Create a realistic portrait of a man in his late 20s with shoulder-length dark hair and light facial hair. He is wearing a dark T-shirt and looking toward the camera. Use a softly blurred indoor background with warm lighting. Frame him from the chest upward. Mood: relaxed and approachable. Aspect ratio: 3:4 portrait.

2. Software testing

Unclear

“Create test cases from this requirement.”

Improved

Act as an experienced Software Test Analyst. Analyze the requirement below and create functional test cases covering positive, negative, boundary and relevant edge cases. Provide Test Case ID, Scenario, Preconditions, Test Steps, Test Data and Expected Result. Do not invent missing requirements.

3. AI legal fact sheet

Unclear

“Can you create a legal AI cheatsheet?”

Improved

Create a one-page AI legal fact sheet for employees who use AI at work in Germany and the EU. Cover the EU AI Act, GDPR, copyright, transparency, human oversight and responsible AI use. Use simple non-legal language and a practical “Before Using AI - Stop & Check” checklist.

Professional Use

Workplace Prompting

Use AI as a drafting, analysis and organization partner while keeping human responsibility for accuracy, commitments and decisions.

Writing and communication

Draft a professional email to employees announcing a change to the onboarding schedule.
Audience: new starters
Tone: reassuring and clear
Include what is changing, what stays the same, what employees need to do and where to ask questions.
Maximum 180 words.

Research and summarization

Summarize the supplied report for senior management.
Use only information supported by the report.
Organize into: key findings, business implications, risks and open questions.
For any point not supported by the source, write "Not established in the source."

Analysis and decision support

Compare the three proposed vendors using: security, implementation effort, cost, support, integration and scalability.
Use the supplied evidence only.
Score each criterion 1-5 and explain each score.
Identify missing evidence.
Do not make the final purchasing decision.

HR and people processes

Appropriate uses include onboarding materials, training activities, communication drafts, aggregate feedback summaries and interview question banks for human review.

Use extra governance for: recruitment screening or ranking, performance decisions, sensitive employee data, automated monitoring or any use that could materially affect an individual.
Specialist Use

Software Testing & Test Management

Prompting can support the testing lifecycle from requirement review to test design, regression analysis, defect reporting and release-readiness reporting.

Part 1: Starting AI in Test Management

Test planning & strategy

Act as a Test Manager. Given this project scope: [paste scope/requirements], identify the key testing risks, suggest an appropriate test strategy, and propose a high-level test plan outline.

Test case design

Act as a Senior QA Engineer. Given this user story: [paste], generate test cases covering happy path, negative, boundary and relevant edge cases.
Output: ID | Scenario | Preconditions | Steps | Expected Result | Priority
Do not invent behavior not present in the requirement. List uncertainties separately.

Test data generation

Generate 20 rows of realistic but synthetic test data for [entity] with fields [list fields]. Include valid, invalid and boundary entries. Output as CSV. Do not use real personal data.

Test automation support

Convert this manual test case into a draft automated test using [framework] in [language]: [paste manual steps].
Use readable selectors and assertions, clear setup/teardown, no hard-coded secrets, and flag assumptions.

Defect and incident management

Act as a QA lead. Here is a defect report: [paste]. Suggest three plausible root-cause hypotheses and one verification step for each. Do not present any hypothesis as confirmed without evidence.

Risk-based regression testing

Given this release scope: [paste changes], identify potentially affected modules. Rank them by testing risk using likelihood x impact and recommend where to focus limited regression-testing time.

Reporting & release readiness

Summarize this test execution data [pass/fail counts, defects, blockers] into a release-readiness report. Separate facts from risk interpretation and highlight blockers, residual risks and missing evidence.

Part 2: When AI is already implemented

The role shifts from generating from scratch toward validating, monitoring, governing and extracting insight.

Validate AI-generated tests

Review this AI-generated test suite for [feature] against the actual requirement: [paste]. Identify test cases that are redundant, incorrect, unsupported or missing. Explain the evidence for each finding.

Analyze performance trends

Given this comparison of AI-generated and human-reviewed test cases over the last three months, identify trends in acceptance rate, false positives, coverage gaps and rework. Do not infer causes unless supported.

Governance and oversight

Given our AI-assisted testing workflow: [describe], identify where mandatory human review checkpoints should exist, where lighter sampling may be sufficient, and what evidence would justify changing the review level.

ROI and quality

Based on these before/after metrics [time, coverage, escaped defects, rework, automation stability], summarize the measurable impact of AI adoption. Distinguish speed improvements from quality improvements.

QA Testing Template

You are a [QA role].
SYSTEM / FEATURE: [describe]
SOURCE: [requirement / user story / acceptance criteria]
TASK: Create candidate test scenarios covering positive, negative, boundary, error-handling and relevant integration/security/accessibility cases.
RULES: Do not invent system behavior. Flag unclear requirements. Separate assumptions from facts.
OUTPUT: ID | Scenario | Preconditions | Test Data | Steps | Expected Result | Priority | Requirement Link

Test Management Template

You are a Software Test Manager.
PROJECT CONTEXT: [scope, release, architecture, dependencies, timeline]
AVAILABLE EVIDENCE: [requirements, test status, defect data, change list]
TASK: Assess release testing from a management perspective.
COVER: scope, quality risks, regression impact, environment/data readiness, execution status, defect blockers, traceability gaps, residual risk, next actions.
RULES: Use supplied evidence only. Mark missing information clearly.
OUTPUT: Executive summary + risk table + actions.
Execution note: GenAI can propose, generate and analyze tests. Actual execution normally depends on test tools, automation frameworks, environments, CI/CD pipelines and controlled integrations.
Agents & Automation

Prompting for AI Agents

Agent instructions define an ongoing role, goals, tools, boundaries, decision rules and stopping conditions.

Agent vs. workflow

Workflow

A mostly predefined sequence of steps. AI may generate or classify information inside the flow, but the path is largely controlled in advance.

Agent

An AI-enabled system that can choose among permitted actions or tools to pursue a goal within defined constraints. The degree of autonomy varies.

Agent instruction framework

ROLE + GOAL + CONTEXT + TOOLS + RULES + APPROVALS + STOPPING CONDITIONS + OUTPUT

ROLE
You are a Software Testing Assistant.

GOAL
Help the testing team identify candidate test coverage for approved requirements.

TOOLS
- Requirements search
- Test repository search
- Defect search
- Draft test-case creator

RULES
- Never invent requirements.
- Do not use unapproved personal data or production credentials.
- Distinguish retrieved facts from suggestions.
- Do not create or approve tests without human authorization.

APPROVAL
A Test Manager must approve generated tests before write-back.

STOP
Ask for clarification when required information is missing or contradictory.

OUTPUT
Proposed scenarios, evidence used, uncertainties and next action.

Design principles for safe automation

  • Least privilege: only the permissions needed.
  • Human approval: gates for high-impact or irreversible actions.
  • Tool boundaries: define which systems can be read or written.
  • Traceability: log evidence, tool calls, outputs and approvals where appropriate.
  • Failure handling: define safe fallback behavior.
  • Evaluation: test representative and adversarial cases before production.

Prompt injection awareness

External content can contain instructions. Treat webpages, files, emails and retrieved documents as untrusted content unless explicitly trusted by the system. Retrieved text must not silently override governing instructions.
Creative Prompts

Prompting for Images

Strong image prompts describe what should be visible, how elements relate to one another and how the final image should feel.

Image prompt elements

ElementDefinitionExamples
SubjectMain person, object, character or scene.A sailing boat; a young professional.
Background / settingLocation, environment, time and context.Warm office; Mediterranean coast at sunset.
Equipment / mediumCamera, lens, film or art medium used to suggest a visual treatment.35mm film look; 85mm lens; watercolor.
StyleVisual language or aesthetic.Photorealistic; editorial illustration; 1930s travel poster.
Lighting / moodIllumination and emotional atmosphere.Soft diffused light; warm cinematic glow.
CompositionFraming, viewpoint and spatial relationships.Close-up; centered subject; palms framing both sides.
Aspect ratioProportional relationship between width and height.1:1, 16:9, 3:4, 5:4.
Realistic imperfectionsNatural details that can reduce an overly synthetic look when appropriate.Skin texture, wrinkles, fabric creases, weathering.
Technical detailsAdditional photographic or rendering cues.Shallow depth of field, macro view, long exposure.

Strong image prompt formula

SUBJECT + SETTING + STYLE + LIGHTING/MOOD + COMPOSITION + TECHNICAL DETAILS

Templates

A [subject] in [setting], [lighting], [camera/lens treatment], [mood], [composition], realistic textures and natural detail, [aspect ratio].
[Subject], [art style] illustration, [color palette], [mood], [composition], clean visual hierarchy, [background], [aspect ratio].
Placement matters. Describe relationships, not just objects: “palms frame the sides,” “boat centered against the sun,” “headline anchored at the bottom.”
Creative Prompts

Prompting for Infographics

For infographics, prompt the information architecture first, then the visual execution.

General infographic prompt

Create a professional infographic about [TOPIC].
Audience: [AUDIENCE]
Purpose: [educate / explain / compare / summarize]
Include: [KEY POINTS]
Organize into clear sections with strong visual hierarchy.
Use icons, diagrams, arrows or visual relationships only where they improve understanding.
Color palette: [COLORS]
Keep text concise and easy to scan.
Format: [vertical / horizontal], [aspect ratio or dimensions].

Content first, design second

I want to create an infographic about [TOPIC].
Do not create the infographic yet.
First:
1. Identify the most important information.
2. Remove unnecessary information.
3. Group related information into sections.
4. Suggest an information hierarchy.
5. Identify what should be visual rather than text.
6. Recommend an infographic structure.
7. Show the proposed content and layout for approval.
Audience: [AUDIENCE]

Process infographic

Create a vertical process infographic titled "How RAG Works."
Audience: employees with limited technical AI knowledge.
Show: User Question → Retrieve Information → Relevant Documents → LLM → Generated Answer
Give each stage a short explanation. Use simple visuals and minimal technical terminology.

Comparison infographic

Create a professional infographic comparing Traditional AI vs Generative AI.
Use two clear columns.
Compare: purpose, input, output, applications, examples, strengths and limitations.
Finish with a one-sentence "Key Difference" summary.

Timeline infographic

Create a vertical infographic titled "The History of Artificial Intelligence."
Present important milestones chronologically.
Each milestone: Year → Event → one-sentence explanation.
Make major breakthroughs visually prominent and keep text concise.
Responsible AI

Responsible and Secure Prompting

Professional prompting also involves data protection, confidentiality, intellectual property, fairness, security and accountability.

Before you prompt

  • Am I using an approved AI tool?
  • Does the prompt contain personal, confidential, restricted or client information?
  • Do I have permission to use the source material?
  • Could the output materially affect a person?
  • Does the task require human review or specialist approval?
  • Will I verify important claims before using them?

Data minimization

Share only the information necessary for the task. Replace real personal or confidential details with synthetic or anonymized examples when appropriate and permitted.

Human accountability

The person or organization using AI remains responsible for deciding whether the output is suitable for its intended use. High-impact uses need stronger governance than low-risk drafting or brainstorming.

Common failure modes

MistakeBetter approach
Vague taskName the exact deliverable and purpose.
No audienceState who will read or use the output.
Irrelevant context dumpInclude only information that changes the answer.
No output formatSpecify the structure you need.
Blind trustVerify important claims and calculations.
Forcing certaintyAsk the AI to state uncertainty and missing information.
Sensitive data in promptsUse approved tools and minimize exposure.
One giant promptBreak complex work into stages with review points.

Quick Reference

Professional Prompt Checklist

Use this before sending an important prompt or accepting an AI-generated result.

CheckQuestion
□ PurposeIs the outcome clear?
□ TaskDid I say exactly what the AI should do?
□ ContextDid I provide the information that materially affects the answer?
□ AudienceDid I identify who the output is for?
□ ConstraintsAre length, scope, tone and exclusions clear?
□ FormatDid I specify how the answer should be structured?
□ SourcesDid I say whether outside information may be used?
□ UncertaintyDid I tell the AI not to guess when information is missing?
□ DataHave I protected personal, confidential and restricted information?
□ ReviewWill a qualified person verify the result before important use?
Final rule: Prompt clearly. Review critically. Use responsibly.

Short definitions for common prompting, LLM and agent terms.

TermDefinition
PromptInput that guides an AI model’s response or action.
Prompt engineeringDesigning and refining prompts to improve the usefulness and reliability of AI output.
LLMLarge Language Model: a model trained on large amounts of data to process and generate language and, in some systems, other modalities.
ParameterA learned numerical value inside a model that contributes to how it processes inputs and generates outputs.

Accuracy & Maintenance

Sources and Update Notes

Prompting practice changes as models and products change. Treat this handbook as a maintained professional reference.

Editorial accuracy notes

  • Prompting advice is guidance rather than universal rules because behavior varies by model, product and task.
  • Generation controls such as temperature, top-p and penalties are platform/model dependent.
  • For chain-of-thought, request concise observable rationale or verification steps rather than hidden internal reasoning.
  • Generated knowledge is not treated as verified evidence; use authoritative sources or RAG when grounding matters.
  • AI agents and automated workflows should use permissions, approval gates, logging, evaluation and safe failure behavior appropriate to risk.

Keep the HTML file in version control or a shared workspace. When adding a new prompt, record the purpose, intended model/system, required inputs, output format, data restrictions, human review and an example evaluation case.
